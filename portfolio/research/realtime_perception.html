Research Question

How can a perception pipeline reduce latency while preserving stable detection behavior for autonomous-system decision loops? This project frames the problem around execution time, data movement, and reliability under changing image conditions.

Approach

  • Profiled the pipeline to identify the stages with the highest contribution to end-to-end latency.
  • Separated preprocessing, inference, postprocessing, and decision-facing outputs for easier measurement.
  • Explored parallel execution paths and GPU-aware optimization where data transfer overhead was justified.
  • Documented constraints so future experiments can compare accuracy, throughput, and deployment complexity.

Evaluation Plan

Latency

Measure frame-to-result time across representative input sequences.

Stability

Track output variance when lighting, motion blur, and object scale change.

Deployment Cost

Compare compute requirements against the target real-time system budget.

Technical Highlights

The strongest big-tech signal in this work is not only a faster algorithm; it is the engineering loop around the algorithm. The page should show profiling evidence, test clips, ablation results, and clear notes about which optimizations helped and which introduced unacceptable complexity.

Future Work

  • Add a reproducible benchmark harness with fixed input sequences and automated latency reporting.
  • Compare CPU-only, GPU-accelerated, and mixed execution paths under the same evaluation protocol.
  • Extend the study toward multi-sensor perception where synchronization becomes part of the latency budget.
