Overview

MANZO is a long-form team game project built around the engineering demands of a larger real-time game: stable gameplay systems, content iteration, rendering support, debugging workflows, and collaboration across code, design, and art. The portfolio goal for this page is to show how I contributed to a production-like game environment rather than only a class prototype.

My Role

Gameplay Systems

Designed gameplay-facing logic with predictable state transitions and clear interfaces for iteration.

Engine Integration

Connected gameplay behavior to rendering, input, scene flow, and debugging support.

Team Workflow

Kept implementation readable so teammates could tune, test, and extend features safely.

Technical Highlights

  • Structured gameplay features around explicit states to reduce hidden dependencies between systems.
  • Used rendering/debugging tools to inspect frame behavior and diagnose visual or performance issues.
  • Separated tunable constants from core logic so designers could iterate without risky code changes.
  • Prioritized graceful failure states for player interactions that could overlap or interrupt each other.

Challenges & Solutions

1 Maintaining Feature Stability
Challenge

As features accumulated, small gameplay changes could accidentally affect unrelated interactions.

Solution

Reduced implicit coupling by isolating ownership, clarifying update order, and keeping data flow visible during debugging.

Reflection

MANZO strengthened my interest in engine-level engineering because it exposed the cost of unclear interfaces over a long project. The biggest takeaway was that good game code is not just clever in isolation; it has to stay understandable while multiple people are actively changing the system.
